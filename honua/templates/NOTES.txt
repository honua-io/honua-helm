{{- if eq (include "honua.migrationsJob.enabled" .) "true" }}
Migrations run out of band: the pre-install/pre-upgrade hook Job
{{ include "honua.migrationsJobName" . }} ran this image with HONUA_MIGRATE_ONLY=true
before the Deployment was applied, and the serving pods run with
HONUA_SKIP_MIGRATIONS=true (they verify the journal and never migrate). Read
its summary:
  kubectl logs -n {{ .Release.Namespace }} job/{{ include "honua.migrationsJobName" . }} | grep '"format":"honua.migrate-only/v1"'
A failed Job leaves the Deployment unchanged. Its exit code and the summary's
code name the reason: 2 invalid configuration, 3 database unreachable,
4 PostGIS missing or unsupported, 5 contract approval needed, 6 unannotated
contract migration, 7 backup command failed, 8 schema newer than this image,
9 migration lock timeout, 10 migration failed, 11 cancelled. For exit 5, review
pendingScripts, set HONUA_APPROVE_CONTRACT_MIGRATIONS to the summary's
contractApproval.nonce (secret.env or extraEnv) for that one upgrade, re-run
the upgrade, then remove it.
Image rollback: serving pods with HONUA_SKIP_MIGRATIONS=true refuse to start
(schema_reader_incompatible) on any journal entry their image does not ship,
so `helm rollback` across an applied migration needs a database restore or a
roll forward. Helm cannot downgrade the schema.
{{- else }}
Migrations run inline during Honua startup. The readiness endpoint
/healthz/ready is the chart's signal that startup and migrations completed.
The default strategy is Recreate so old and new server versions do not run
against the same database during a migrating upgrade. Before upgrading, check
GET /api/v1/admin/deploy/preflight and take a database backup. To run them out
of band in a pre-upgrade Job instead (the recommended production path), set
migrations.job.enabled=true with a honua-server image that ships migrate-only
mode.
{{- end }}

This release runs in SingleInstance mode with one server replica. To scale out to
horizontally autoscaled HA, supply an override that:
  1. sets config.env.Deployment__Mode: "MultiNode";
  2. enables autoscaling (autoscaling.enabled=true) or raises replicaCount;
  3. provides ConnectionStrings__redis; and
  4. sets a shared cloud FileStorage:Provider (AwsS3 or AzureBlob; Local is
     rejected in MultiNode), with its bucket/region or connection-string/container.
The chart fails at render time if autoscaling is enabled while
Deployment__Mode is SingleInstance, so change these settings together.
